# Divise SSV Bozen Maschile — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sezione admin "Divise": inventario di maglia + pantaloncino per gruppo/numero/taglia/libero, assegnazione
ai ragazzi, riepilogo per taglia, esportazione Excel/WhatsApp filtrata per gruppo.

**Architecture:**
- Una tabella Supabase `divise` protetta da RLS solo admin.
- Logica pura in `src/lib/divise.ts` e `src/lib/esportaDivise.ts`, coperta da test Vitest.
- Hook React Query in `src/hooks/useDivise.ts`.
- Una pagina `DivisePage` con tre popup (form, blocchi, export) che seguono lo stile di `RosterPage` ed `EsportaAtleti`.

**Tech Stack:** React 19, Vite 8, TypeScript strict, Supabase, @tanstack/react-query 5, xlsx (import dinamico),
Vitest (nuova devDependency).

**Spec:** `docs/superpowers/specs/2026-10-21-divise-design.md`

## Global Constraints

- **Accesso solo admin:** rotta dentro `<RequireAdmin>`, voce di menu dentro il blocco `isAdmin` di
  `ProtectedLayout.tsx`, RLS `my_role() = 'admin'` per tutte le operazioni, `revoke all on divise from anon`.
- **Gruppi, nell'ordine:** `'U17' | 'U14-15' | 'U12-13'`. `null` = "Da assegnare".
- **Taglie, nell'ordine:** `'XS','S','M','L','XL','XXL','3XL'`.
- **Numero:** intero da 0 a 99.
- **Ogni ragazzo:** al massimo una divisa con `libero = false` e una con `libero = true`.
- **Numeri doppi:** stesso `gruppo` non nullo, `numero` e `libero` → solo avviso, mai blocco.
- **`roster_id`:** senza foreign key. Se l'id non esiste più in `roster`, la divisa mostra "non più in rosa".
- **`giocatore_nome`:** sempre valorizzato quando la divisa è assegnata, anche se il ragazzo viene dalla rosa
  ("Nome Cognome").
- **Testi in italiano**, con lo stile e le classi esistenti (`settings-modal`, `btn`, `btn ghost small`, `field`, `row`).
- **Verifica:** `npx tsc -p tsconfig.app.json` (non `tsc --noEmit -p tsconfig.json`, che non controlla nulla),
  `npm run build`, `npx vitest run`.
- **Database condiviso tra locale e produzione:** ogni prova usa dati di prova e alla fine li cancella.
  Le migrazioni si applicano dall'editor SQL di Supabase nel browser. Le credenziali le inserisce Manuel.
- **Commit:** terminano con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Il push è il passaggio finale
  dell'ultimo task, dopo l'ok di Manuel sull'esempio.

## Review Focus

1. **Stesso ragazzo con due divise dello stesso tipo inserite a mano con maiuscole o spazi diversi**
   ("lorenzo  Riccadonna"): va riconosciuto come conflitto (test in Task 2, vincolo in Task 1).
2. **Spostare un ragazzo con "Sposta qui"** deve liberare la vecchia divisa *prima* di assegnare la nuova,
   altrimenti scatta il vincolo univoco (Task 4, ordine delle due update).
3. **Blocco con "dal" maggiore di "al", fuori da 0–99 o più di 100 divise** → messaggio, nessuna creazione
   (test in Task 2).
4. **Divisa da libero assegnata a un ragazzo che ha già quella normale** → consentito, nessun conflitto
   (test in Task 2).
5. **Export con un gruppo selezionato vuoto o senza nessun gruppo scelto** → Excel e WhatsApp non vanno in errore:
   gruppo vuoto con la scritta "nessuna divisa", pulsanti disattivati se non c'è nessun gruppo (Task 3 e Task 7).
